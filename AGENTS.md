## Что это за репозиторий

`CampLink-DataBase` — репозиторий **проектирования** БД и требований сервиса **Camplink**: сервис бронирования товаров и услуг на базе отдыха. Здесь **нет кода** — нет сборки, линтера и тестов. Работа ведётся только со схемой БД, диаграммами и документацией требований.

Ключевые сущности домена: **ресурс** (товар, поштучный или прокатный), **клиент**, **бронирование** (со строками бронирования), **запасы** (журналы движения), **календарь** (рабочие/нерабочие дни).

## Структура

- `README.md` — главный артефакт: требования и описание доменной модели системы (на русском). Править при изменении бизнес-требований.
- `Scheme/` — схемы БД:
  - `DatabaseScheme.erd.json` — ER-диаграмма в формате **ERD Editor** (см. `$schema` dineug/erd-editor). Содержит служебные структуры `lww`/`collections`, которые не нужно править руками — редактировать в ERD Editor.
  - `camplink.drawio` — визуальная схема БД в формате **diagrams.net** (draw.io). Открывается в app.diagrams.net.
- Рабочая ветка — `feature/IV-0001`; целевая ветка PR — `main`.

## Схема БД (актуальное состояние)

По `Scheme/DatabaseScheme.erd.json` на текущий момент проработаны только наброски:

- `FixedAsset` — сущность ресурса: `AssetId BIGINT PK`, `DealType INT` (enum: 0 — прокат, 1 — продажа). Остальные таблицы (`UserAccount`, `Location`) и связи пока не проработаны (пустые контейнеры).

Обрати внимание: JSON-схема (erd) и drawio-диаграмма развиваются независимо и могут расходиться. При изменении одной — проверь, не требует ли синка другая, и синхронизируй их как отдельный шаг.

- README содержит список будущих задач (например: переписать README в Markdown, добавить диаграмму BPMN 2.0). Сущности, требуемые доменом (бронирование, клиент, запасы, календарь), в ERD пока не отражены — их предстоит добавить в схему.
