Camplink - сервис бронирования товаров и услуг на базе отдыха.

Проблема пользователя - заблоговременно спланировать свой отдых.
Проблема владельца - финансовый учёт, планирование и распределение ресурсов (товары, инвентарь, услуги).

Описание системы: 
Camplink должен предоставлять информацию о доступном количество ресурсов в разрезе даты для поштучных товаров, в разрезе дата-время для прокатных товаров. Для упращения работы с прокатом считаем, что весь прокатный инвентарь можно арендовать минимум на час, то есть минимальная единица учёта проката - час. Также для простоты учёта остатки товаров существуют только в рамках одной даты. Для некоторых прокатных товаров есть ограничение по минимальному времени бронирования, например беседку можно забронировать минимум на сутки.
Camplink должен учитывать ввод остатков и бронирования при расчёте доступного кол-ва.
Camplink должен владеть информацией о клиентах и их бронированиях.
Camplink должен предоставлять финансовую информацию владельцам.

ИНВЕНТАРИЗАЦИЯ - ВВОД ОСТАТКОВ

По каждому ресурсу создаётся журнал запасов с типом движения "ввод остатков" на конкретную дату. Если товар поштучный, то на конкретную дату создаётся одна строка с доступным количеством и ценой товара на этот день. Если товар прокатный, то создаётся не больше 24-х строк на каждый час в сутках.


ФИН. ОТЧЁТ

За указанный период формируется информация о запасах в статусе расход + куплено.


БРОНИРОВАНИЕ

Сервис должен уметь формировать список доступных русурсов на конкретную дату, уметь выполнять резерв ресурсов под конкретного клиента, знать информацию о всех бронированиях, учитывать статус оплат и бронирования.

Get:

формируется список доступных русурсов на конкретную дату.

Get: Клиент ID

формируется информация о бронированиях клиента

Get: Бронирование ID

формируется информация о бронированиях клиента

Post:

Добавляется запись в справочник клиентов, создаются записи в журналах бронирование и журналах запасов.

In:

Клиент
- название
- описание
- контакты

Ресурс
- Ресурс ID
- Количество
- Дата
- Время начала
- Время окончания

Out:
- Бронирование ID


УПРАВЛЕНИЕ ОПЛАТОЙ И БРОНИРОВАНИЕМ 

Записи запасов переходят в требуемый статус

In:
- Бронирование ID
- тип оплаты: нал, безнал
- статус оплаты: не оплачено, оплачено
- статус бронирования: подтверждено, отменено

Out:

сообщение об успешной оплате по бронированию или об успешном бронировании

## Схема БД (актуальное состояние)

Источник истины — `Scheme/DatabaseScheme.erd.json` (ERD Editor). Схема отражает
доменные таблицы DWH из `Scheme/camplink.drawio`. Таблицы и колонки — на
английском, enum-значения указаны в комментариях к колонкам (см. файл схемы).

### Client (Клиенты)
- `ClientId` BIGINT PK
- `Name` VARCHAR — название
- `Description` VARCHAR — описание
- `Contacts` VARCHAR — контакты

### Resource (Ресурсы)
- `ResourceId` BIGINT PK
- `Name` VARCHAR — название
- `Description` VARCHAR — описание
- `ItemType` INT — тип товара: поштучный / прокатный
- `UnitType` INT — ед. изм.: штука / кг / литр / час
- `Price` DECIMAL(10,2) — цена за 1 ед. изм.
- `Multiplicity` INT — кратность
- `PhotoUrl` VARCHAR — ссылка на фото

### Booking (Бронирования)
- `BookingId` BIGINT PK
- `ClientId` BIGINT FK → `Client.ClientId`

### BookingLine (Строки бронирования)
- `BookingLineId` BIGINT PK
- `BookingId` BIGINT FK → `Booking.BookingId`
- `ResourceId` BIGINT FK → `Resource.ResourceId`
- `ClientId` BIGINT FK → `Client.ClientId`
- `Quantity` INT — количество
- `Price` DECIMAL(10,2) — цена за 1 кол-во
- `Date` DATE — дата
- `StartTime` DATETIME — время начала
- `EndTime` DATETIME — время окончания

### Inventory (Запасы, журнал движения)
- `InventoryId` BIGINT PK
- `ResourceId` BIGINT FK → `Resource.ResourceId`
- `BookingId` BIGINT FK → `Booking.BookingId` (nullable — пусто при «вводе остатков»)
- `MovementType` INT — тип движения: ввод остатков / приход / расход
- `OperationType` INT — тип операции: резерв / подтверждено / куплено / отменено
- `PaymentType` INT — тип оплаты: нал / безнал
- `ReservedDate` DATE — зарезервированная дата
- `ReservedTime` DATETIME — зарезервированное время
- `EventTime` DATETIME — время события
- `Quantity` INT — количество
- `Price` DECIMAL(10,2) — цена за 1 ед. изм.

### Calendar (Календарь)
- `CalendarId` BIGINT PK
- `Date` DATE — дата
- `DayType` INT — тип дня: рабочий / выходной / нерабочий

### Связи (FK, 1:N)

FK-связи (рёбра ERD) отмечены колонками со ссылкой на PK родительской таблицы;
графически рёбра расставляются в ERD Editor. Все связи — **1:N (One-to-Many)**,
ненаследуемые (non-identifying), FK живут на стороне Many.

| № | From (Many, FK) | To (One, PK) | Связь |
|---|---|---|---|
| 1 | `Booking.ClientId` | `Client.ClientId` | Client 1—N Booking |
| 2 | `BookingLine.BookingId` | `Booking.BookingId` | Booking 1—N BookingLine |
| 3 | `BookingLine.ClientId` | `Client.ClientId` | Client 1—N BookingLine |
| 4 | `BookingLine.ResourceId` | `Resource.ResourceId` | Resource 1—N BookingLine |
| 5 | `Inventory.ResourceId` | `Resource.ResourceId` | Resource 1—N Inventory |
| 6 | `Inventory.BookingId` | `Booking.BookingId` | Booking 1—N Inventory |

Семантика: один клиент — много бронирований; бронирование — много строк
бронирования; ресурс встречается в строках бронирования и имеет журнал запасов;
бронирование порождает записи в журнале запасов.
